### ⚠️ Environment facts that cost hours to rediscover

- **The backend uses `pnpm`, NOT npm.** `npm install` dies with
  `Cannot read properties of null (reading 'matches')` — npm's arborist choking on pnpm's
  symlinked `node_modules`. Use `pnpm add`.
- **The AI service on `:8000` orphans a CHILD process.** uvicorn spawns a child that holds
  the socket; kill the parent and the child keeps `:8000` bound while `Get-Process` reports
  the netstat PID as "not found". Find it with
  `Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select ProcessId,ParentProcessId,CommandLine`
  and kill the CHILD.
- **The Redis container keeps losing its port mapping.** `docker ps` shows `Up`, but
  `ports=6379/tcp` (exposed, not published) and `docker port jobfit-redis` is empty. It must
  be recreated — you cannot add a mapping to an existing container:
  `docker rm -f jobfit-redis && docker run -d --name jobfit-redis -p 6379:6379 redis:7-alpine`
- After `schema.prisma` changes: hand-write the migration SQL, `npx prisma migrate deploy`
  (never `migrate dev`), then `npx prisma generate` — which fails with EPERM unless the
  backend dev server is stopped.
- AI-service prompt `.txt` files are `lru_cache`d: restart the service after editing one.

## 3. What was built (08-05 → 08-07)

### A. Résumé parsing — the extractor was the bug, not the model
`docs/RESUME_EXTRACTION_PLAN.md`

`pdf-parse` emitted text in PDF content-stream order, not reading order. On the reference CV
the job title appeared **four lines below its own bullets**, education dates pooled away from
their degrees, and a whole SKILLS column was stranded between two schools.

Replaced with **`pdfjs-dist@3.11.174`** (pinned: v4+ is ESM-only, this project is
`module: commonjs`) reconstructing reading order from x/y. Also added a `projects` field
across all three repos, and made parsing **AI-only** (no silent regex fallback).

**Measured 2×2 on the reference CV:**

| | `qwen3:0.6b` | full `qwen3` |
|---|---|---|
| scrambled text | 2/6 | 4/6 · 761s |
| reading-order text | **4/6** | 5/6 · 504s |

**The load-bearing finding:** both scrambled cells miss two skills *regardless of model size* —
the extractor had relocated them, so the information is absent from the input. A bigger model
provably cannot buy its way out of that class of error.

Prompt v4 is default (`resume_parse_v4.txt`); v1–v3 retained so old measurements reproduce.
Dates went 0/7 → 8/8 correct; the invented-employer bug improved (~43% → ~87% correctly null)
but is **not solved**.

### B. Internal vs external jobs
`docs/INTERNAL_EXTERNAL_JOBS_PLAN.md`

A user could "Apply" to all 51 jobs, but 43 are ingested from TheMuse — the application was
stored and the user believed they had applied for a job they had not. `Job.sourceType` now
gates it, **enforced server-side**, with "Apply Externally" in the UI.

### C. Reranker ON
Measured **MRR@10 0.63 → 0.75 (+20%)**, off since the day it was measured. Now on via
`MATCHING_RERANK_ENABLED`. The eval harness passes explicit booleans so a baseline run can
never inherit the deployment's setting.

### D. Skill-gap + LLM requirement extraction
`POST /job/requirements` reads requirements out of free-text descriptions —
**0.937 groundedness across 44 postings**, with invented ones dropped (12 were, including
"Experience with Docker and Kubernetes" on a **Welding Engineer** posting).

`GET /recommendations/skill-gap?jobId=` returns covered/missing requirements. **No percentage.**

### E. AI Recruiter (Phases 1–4 of `docs/AI_RECRUITER_PLAN.md`)
Applying to an internal job now screens the candidate, stores a snapshot, advances
`SUBMITTED → SCREENING`, and shows the employer a **ranked** applicant list with reasons.

```
strong     6/7 covered      partial  3/7      junior  1/7      unrelated  0/7
```

**Phase 5 (auto-advance threshold) is deliberately NOT done — see §5.**

### F. Security fixes found while testing
- **Candidate could set any status on their own application** — including `OFFER` and
  `ACCEPTED`, which then appeared in the employer's pipeline as if the employer decided it.
- **Employer could set `WITHDRAWN`/`ACCEPTED`** — the candidate's decisions.
- **The employer path had NO transition validation at all** — it wrote status straight
  through Prisma, so `SUBMITTED → ACCEPTED` was possible with no interview or offer.
- **Login did not clear the query cache** — logging in as a different user could serve the
  previous user's cached data, and caused "wrong dashboard until I refresh".

## 4. Things removed because they were fabricated

- **"Fair Match" widget** — bars were `job.match ± 3` where `job.match` is hardcoded `0`,
  under literal HTML claiming "React, TypeScript and Node.js align perfectly" for every job
  and user. Rebuilt against a real endpoint (`GET /recommendations/for-job`).
- **Company panel** — hardcoded "Technology & Software · 500-1000 employees · Series C,
  $120M · Glassdoor 4.2/5" for every employer. This published **invented facts about real
  businesses**: G&W Electric, an electrical equipment manufacturer, was shown as a Series C
  software startup. Now renders only non-null columns (most are empty — that is correct).
- **"92% confidence" badge** on résumé parsing — `parsedBy === "ai" ? 92 : 75`, a constant.
  It read 92% over a parse scoring 2/6.

**Still fabricated, NOT fixed:** `job.mappers.ts` defaults `type: "Full-time"`,
`level: "Mid-level"`, `industry: "Technology"` on every job. Job cards render the first two
as pills, so every card claims "Full-time · Mid-level" regardless of the posting.

## 5. Measurements that said NO (do not re-litigate without new data)

1. **LLM `fitScore` is unusable.** ρ = 0.137 (v1) / −0.065 (v2) over 150 hand-graded pairs;
   BAD scored *higher* than GREAT. It appears in **no** user-facing path. Every "match score"
   shipped is the **deterministic** scorer (embedding cosine + rules), which is a different
   thing.
2. **Semantic embeddings for skill↔requirement matching FAILED.** Measured before building:
   the software candidate scored **higher than the mechatronics candidate on an automotive
   job** (0.629 vs 0.482), and "Automotive Eng Tech" ↔ "Automotive Industry" (0.467) ranked
   *below* "Teamwork" ↔ "collaborate as a team". No threshold separates them. Shipped
   distinctive-word matching instead.
3. **AI Recruiter auto-advance threshold — not measurable yet.** The only data is 4 candidates
   on 1 job, and **I wrote both the candidates and the expected ranking**, so a threshold
   from it is an assumption laundered through a script. Needs real applications or ~20–30
   hand-labelled ones judged by someone else. The ranked list already delivers the value.

## 6. Open issues, roughly by value

**1. Résumé upload HANGS when Redis is down.** `queue.addJob` has no timeout, and BullMQ's
ioredis buffers forever, so `POST /resumes` never returns and the UI sits at
"Uploading… 100%". **This has bitten twice today** and left **3 résumés stuck PENDING**. The
file and row are already saved at that point; the frontend already renders the right state
(`hasTimedOut` → "saved, analysis still queued"). Put a timeout on the enqueue and return 201.
*Small fix, highest value.*

**2. `qwen3:0.6b` parsing is unreliable.** 8 runs on identical input scored 2, 4, 4, 4, 5, 5,
6, 6 out of 7. The spread *within* one prompt version is wider than the gap *between*
versions — so single-run comparisons mean nothing, and three prompt versions moved the mean
by ~0.6. This is capacity, not prompting.

**3. Invented employer names.** ~1 run in 8 still fabricates a company from a description
that only *characterises* the employer. Same faithfulness class as the Phase C failures.

**4. Job cards show fake `type`/`level`.** §4 above.

**5. Seeded candidates have no embeddings**, so their `skills` sub-score is 0 and match
scores cluster at 46–50%. Run the embedding backfill to make the score meaningful — and to
test whether it adds anything over coverage.

**6. `averageMatchScore` in employer analytics is always null** — it reads the `matchScore`
table, which has 0 rows and nothing writes to it.

**7. Phase D (GPU) still hardware-blocked.** See `docs/RAG_PHASE_D_HANDOFF.md`. Note
`jobfits-ai-service/runpod-worker/` is untracked, half-built, and Serverless — the memo says
use a **Pod** for the Step-0 measurement, not Serverless.
