## 2. What shipped since the last handoff

### `42affb5` + `6651d8f` — OCR for photographed and scanned CVs

A PDF with no text layer — a photo of a CV that a phone wrapped in a PDF — was accepted at
upload, produced an empty string in the parser, and failed with a message pointing at the
AI service. Nothing said the file had no text in it. That is the common case in this
market, where documents are photographed rather than scanned.

| Upload | Before | Now |
|---|---|---|
| PDF with a text layer | works | works, **OCR not invoked** (verified: 0 calls) |
| DOCX | works | unchanged |
| Scanned PDF (photo in a PDF) | accepted → failed, blamed the AI | **OCR, ~3.3 s** |
| PNG / JPEG / WebP | rejected at the picker | **OCR, ~0.4 s** |
| Unreadable photo | — | fails with *"Try a sharper photo taken straight on, in good light."* |

**Design decisions worth not re-litigating:**

- **`tesseract.js`, not `pytesseract` in the AI service.** It is WebAssembly, so it needs
  no system binary and runs on Cloud Run unchanged. More importantly the AI service lives
  on a laptop behind a tunnel — OCR there would mean a photographed CV only parses while
  that laptop is awake. OCR runs in the BullMQ worker that already did PDF and DOCX.
- **Page images are read out of the PDF, not rendered.** Rendering needs a canvas
  implementation — a native dependency in the deploy — to redraw pixels already sitting in
  the file.
- **Khmer is loaded alongside English** (`eng+khm`). A scanned CV here may be partly in
  Khmer script, and an English-only engine returns confident nonsense rather than nothing.

**Three traps found while building it, all fixed — do not undo them:**

1. `tesseract.js` caches language data into the **process CWD**, which is `/app` in the
   container and **read-only on Cloud Run**. It also wrote `eng.traineddata` beside
   `package.json` on the first local run. `cachePath` now points at the OS temp dir **and
   the service creates that directory** — tesseract does not create it and does not
   complain, it silently stops caching and re-downloads ~15 MB every time.
2. RGBA page images were passing their alpha through. A transparent region reaches OCR as
   ambiguous pixels and a fully transparent one as a blank page; they are now composited
   onto white, which is what the paper actually looks like.
3. A read below 40% confidence is discarded. A blurred photo produces confident-looking
   garbage, and filling a profile with invented text is worse than failing the upload.

**The bug that would have broken the first test** (`6651d8f`): the parser called
`parseResume(text, fileType as FileType)` and that **cast hid the problem from the
compiler** — `FileType` was `'PDF' | 'DOCX'` on both sides. A photographed CV would OCR
perfectly and then be rejected with a 422. The field is validated by the AI service and
**never used** (`ResumeService.parse` reads only `text` and `prompt_version`), so the
rejection bought nothing. `IMAGE` is now in the enum on both sides.

### Google sign-in — live

`POST /auth/google` verifies a Google ID token and either signs the matching account in or
creates a `JOB_SEEKER`. Verified live on Vercel: the client id is present in
`/_next/static/chunks/610-*.js`, so the button renders on the deployed frontend.

Policy that is deliberate and should survive future edits: lookup is by Google's stable
`sub` **first** and email second (emails get recycled, subject ids do not); an **ADMIN is
never** signed in this way; an **unactivated EMPLOYER is refused** because activation is a
gate Google must not route around.

### Legal pages — live, and a domain that was never ours

`/terms` and `/privacy` exist and are reachable (verified: the contact on the live page is
`soviseth869@gmail.com`).

**`jobfits.io` is not ours.** It is a different product — *"jobfits — AI-Powered Career
Coaching Tools"*, served from `185.158.133.1`. This codebase carried it as the canonical
URL in `layout.tsx`, `robots.ts` and `sitemap.ts` since before the legal pages existed, and
the legal pages inherited it: the published contact read `support@jobfits.io`, an address
on a stranger's domain. Fixed in `d0ca028`. **Do not reintroduce it.** The real site is
`https://jobfit-frontend-six.vercel.app` until a domain is actually bought.

⚠️ The OAuth client's *Authorized JavaScript origins* list still contains
`https://jobfits.io`. Harmless — Google will never see a request from there — but it should
be removed from the Google Cloud Console for the same reason.

## 4. Known gaps — real, and none of them block the redeploy

**The labelled evaluation set is empty.** `matchLabel` count is **0**. The 20% improvement
and ρ 0.662 figures quoted on the slides came from a set that no longer exists, almost
certainly destroyed by `onDelete: Cascade` on both `MatchLabel` foreign keys
(`schema.prisma`) — deleting a user erases their evaluation pairs. The Legal Decision
Framework already records the fix as **D20**: change to `SET NULL` or decouple. Until then,
the measurement cannot be re-run or demonstrated.

**Two of four profiles have `embeddingStatus: FAILED`**, so those accounts get no
recommendations at all, whatever screen they land on.

**Production has no AI service of its own.** `AI_SERVICE_URL` points at the laptop's fixed
ngrok domain (`stellar-nanny-thermos.ngrok-free.dev`). Laptop on → AI works; laptop off →
`/health/ready` reports `ai.degraded` and everything that does not need AI keeps serving.
That is a demo arrangement. A real deployment changes one substitution in `cloudbuild.yaml`.

**`support@jobfits.io` was replaced by the Gmail address, but no mailbox is promised
anywhere.** The legal pages now publish `soviseth869@gmail.com`. If that is not where
privacy requests should go, change it in
`jobfit-frontend/src/features/marketing/components/legal-page.tsx` (`SUPPORT_EMAIL`).

**The pricing page still shows Pro $19 / Enterprise $49 as purchasable** while `/terms`
says nothing is charged and `payment.api.ts` confirms there is no payments backend. Those
two pages contradict each other.

**Outstanding Legal Decision Framework items** (root `JOBFIT_LEGAL_DECISION_FRAMEWORK.md`
